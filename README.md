# Travel Nova

Локальный персональный планировщик путешествий по России. Он собирает три
готовых варианта поездки из перелёта, отеля, афиши и мест рядом, а выбранный
маршрут можно менять в чате. На главной можно заполнить обычную форму или
описать поездку своими словами: сервис извлечёт даты, состав, длительность,
бюджет, темп, занятия и пожелания по климату, явно покажет допущения и сразу
запустит тот же планировщик.

Насыщенность программы зависит от выбранного темпа: примерно одно событие на
четыре дня для спокойного, на три для обычного и на два для активного, с
безопасным верхним лимитом. Рестораны не фиксируются в таймлайне: приложение показывает до
пяти вариантов отдельными группами рядом с отелем и каждым событием, учитывая
подтверждённые ресторанные предпочтения из локального банковского профиля.
Профиль также агрегирует read-only историю заказов афиши и отелей: типы и жанры
событий, площадки, привычное время и цену, размер компании, звёздность, питание
и длительность проживания. Для возрастных ограничений сохраняется только
диапазон и допустимость 18+ — дата рождения и пол не покидают процесс MCP.
Сырые операции, order id, места, имена гостей, контакты и реквизиты в профиль
Travel Nova не записываются.
В программе по дням показывается прогноз Open-Meteo на ближайшие 16 суток, а
для дальних дат — типичная температура и частота осадков по данным ERA5 за
1991–2020 годы.

## Быстрый запуск

Нужен Node.js 22 и сохранённая сессия `tbank-mcp`.

```bash
npm install
cp travel-api/.env.example travel-api/.env
npm run dev
```

Откройте `http://127.0.0.1:5173`. API работает на
`http://127.0.0.1:3000`.

Для менеджерских экспериментов без API и веб-интерфейса есть отдельный
Python-only MCP. npm здесь только устанавливает окружение и передаёт процесс
Python-серверу:

```bash
npx -y @travel-growth-inspiration/mcp login
npx -y @travel-growth-inspiration/mcp serve
```

Он stateless/read-only, использует только T-Bank, OpenStreetMap/Nominatim и
Open-Meteo и не зависит от `travel-api`, SQLite, SSE или LLM Proxy.

Пока реальный банковский контур подключается, по умолчанию используется
`DATA_MODE=demo`: локальный интерфейс и все сценарии можно проверить без MCP.
Для реальных read-only источников T-Bank и OpenStreetMap явно укажите
`DATA_MODE=auto`; он честно показывает неполный результат при отказе
необязательного источника. `DATA_MODE=live` включает строгую диагностику
обязательных источников. Демонстрационные данные никогда не подмешиваются в
реальную подборку.

Для более полных ресторанных карточек можно подключить Places API 2ГИС. Создайте
демо-ключ в [Менеджере Платформы 2ГИС](https://platform.2gis.ru/), добавьте
`TWOGIS_API_KEY` в `travel-api/.env` и перезапустите API. При наличии ключа 2ГИС
становится основным источником ресторанов, а OpenStreetMap остаётся источником
достопримечательностей и резервным поиском. Без ключа поведение не меняется.

Для режима «Описать словами», персональных названий и разбора изменений в чате
укажите `LLM_PROXY_API_KEY` в окружении или в игнорируемом файле
`travel-api/config.env`. Свободное описание разбирается по строгой JSON-схеме;
при невалидном ответе выполняется одна попытка исправления. В LLM Proxy передаются
только текст, текущая дата, часовой пояс и публичный каталог городов и тегов —
банковский профиль и операции не передаются. Если LLM Proxy недоступен, обычная
форма продолжает работать, а текстовый режим показывает понятную ошибку.

По умолчанию используется внутренний OpenAI-совместимый endpoint
`https://llm-proxy.t-tech.team/v1` и модель `tgpt/text.instant.medium`.
При необходимости их можно переопределить через `LLM_PROXY_BASE_URL` и
`LLM_PROXY_MODEL`. Один клиент и одна модель используются как для оформления
вариантов, так и для разбора свободного описания и команд чата.

Медленные потоковые источники имеют отдельные безопасные лимиты ожидания:
`FLIGHT_PROVIDER_TIMEOUT_MS` и `HOTEL_PROVIDER_TIMEOUT_MS`. Они не увеличивают
таймаут быстрых банковских и OSM-вызовов.
Для фиксированного города гибкие окна дат проверяются параллельно. Отдельные
лимиты `MCP_FLIGHT_MAX_CONCURRENCY` и `MCP_HOTEL_MAX_CONCURRENCY` позволяют
одновременно выполнять до шести поисков перелётов и трёх поисков отелей, не
ускоряя за их счёт профильные и прочие MCP-вызовы.

Погодная интеграция не требует API-ключа. При необходимости адреса сервисов
можно переопределить через `OPEN_METEO_FORECAST_URL` и
`OPEN_METEO_ARCHIVE_URL`; общий лимит ожидания задаёт `PROVIDER_TIMEOUT_MS`.

## Команды

```bash
npm run dev        # API и веб-интерфейс
npm run typecheck  # проверка TypeScript
npm run build      # production-сборка всех workspace
```

## Состав

- `travel-api` — Express API, SQLite, SSE, компилятор и провайдеры;
- `travel-web` — React + Vite, карточки, карта и чат;
- `packages/contracts` — общие Zod-схемы и TypeScript-типы;
- `packages/travel-mcp` — POSIX npm-bootstrap для Python-only Travel MCP;
- `tbank-mcp` — локальный банковский MCP с обратносуместимым JSON-режимом для
  read-only интеграции Travel Nova; обычные текстовые ответы сохранены.

MCP-клиент содержит физический allowlist только для read-only travel- и
профильных методов. Бронирование, сообщения, корзины, переводы и оплаты через
Travel Nova вызвать нельзя. Сырые операции и банковские credentials не
передаются ни в LLM Proxy, ни в OpenStreetMap.

Перед подбором состояние источников можно проверить через
`GET http://127.0.0.1:3000/api/v1/system/readiness`. Проверка не возвращает
credentials, номера счетов или содержимое банковской сессии.
