# Составление поездки

Этот skill — стартовая точка, когда пользователь хочет не отдельный билет или
отель, а целую поездку: транспорт, проживание, бюджет, варианты и итоговый
дайджест.

## Сначала собери brief

Перед поиском уточни или зафиксируй безопасными дефолтами:

- destination и город отправления, если нужен транспорт;
- приемлемые даты или диапазон дат;
- количество гостей: adults, children и infants;
- предпочтения по транспорту: авиа/ЖД, прямой рейс, багаж, пересадки;
- предпочтения по проживанию: район, бюджет, звёзды, питание, отмена;
- интересы и ограничения по активностям. Не добавляй активности, если для них
  нет доступного источника/тула.

Не выдумывай значения и не выводи их из несвязанных прошлых поисков. Один и тот
же состав гостей передавай в авиа- и hotel-тулы.

## Подключи узкие skills

Если нужны отели, сначала прочитай и выполни:

```text
read_instruction("tbank-hotel-search")
```

или используй соответствующий skill `tbank-hotel-search`.

Если нужны авиабилеты, прочитай:

```text
read_instruction("tbank-flight-search")
```

или используй `tbank-flight-search`.

Эти skills возвращают фактические варианты, цены, ids, тарифы и hand-off ссылки.
Сохраняй их без изменений. Текущая travel-only поверхность не публикует
Afisha, cinema, nearby-place или marketplace tools, поэтому события и места
рядом не выдумывай.

## Собери конкретный выбор

До финального отчёта должны быть определены:

- основной outbound/return транспорт либо поездные сегменты;
- альтернативные flight-пары в `flightOptions`, если пользователь просил другие
  даты, прямые рейсы или варианты;
- shortlist отелей с реальными `hotelId`;
- актуальные rates/room ids и условия, если они нужны для сравнения;
- `reviewDigest` по каждому финальному отелю, если hotel skill загрузил отзывы;
- бюджет и warnings о неполных/нефинальных данных.

Каждый элемент `flightOptions` содержит:

```json
{
  "label": "короткое название",
  "comment": "фактические плюсы, минусы и сдвиг дат",
  "directions": [
    {
      "direction": "outbound|return",
      "fromCode": "код из flight_search",
      "toCode": "код из flight_search",
      "date": "дата из flight_search",
      "carriers": ["номер рейса из flight_search"]
    }
  ]
}
```

Не добавляй в варианты выдуманные рейсы, цены, hotel ids или URL.

## Получи итоговый дайджест

Вызови единственный публичный report-тул:

```text
get_trip_report(request, output_mode="html" | "markdown")
```

`request` содержит brief поездки и фактические данные выбора. Если hotel skill
загрузил отзывы, передай его компактный `reviewDigest` внутри соответствующего
hotel item; composer сохраняет digest, но сам `hotel_reviews` не вызывает:

```json
{
  "title": "...",
  "destination": "...",
  "dateFrom": "YYYY-MM-DD",
  "dateTo": "YYYY-MM-DD",
  "travelers": 2,
  "layout": "full",
  "flights": [],
  "flightOptions": [],
  "hotels": [
    {
      "hotelId": "...",
      "roomId": "...",
      "reviewDigest": {
        "sampleSize": 10,
        "summary": "краткая сводка выборки",
        "pros": ["..."],
        "cons": ["..."],
        "suitableFor": "кому подходит"
      }
    }
  ],
  "recommendedHotelId": "..."
}
```

`output_mode="html"` возвращает JSON с готовой HTML-страницей, warnings и
advice; Markdown в этом режиме не возвращается. `output_mode="markdown"`
возвращает только Markdown-дайджест. `layout="compact|full"` влияет только на
HTML.

Checkout URL — это hand-off пользователю, а не бронь и не оплата. Если точной
ссылки нет, напиши «Ссылка T-Bank недоступна» и не создавай URL вручную.
