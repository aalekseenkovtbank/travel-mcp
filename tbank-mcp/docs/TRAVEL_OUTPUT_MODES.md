# Travel Nova: режимы результата и отельный блок

Это каноническая инструкция для представления отдельной подборки отелей и полной
поездки. Правила поиска транспорта, бюджета и программы остаются в
`TRIP_GENERATION.md`; точные hotel-вызовы — в выбранном task-specific skill.

## Режим результата

Канонический инструмент итогового отчёта —
`get_trip_report(request, output_mode="html" | "markdown")`.
Request собирается по [TRIP_GENERATION.md](TRIP_GENERATION.md); события
добавляются после прямого `afisha_catalog`, без предварительного `search_app`.

- `html` — для хоста с HTML-превью: инструмент возвращает JSON с готовой
  HTML-страницей, warnings и advice. Markdown в этом режиме не возвращается.
- `markdown` — для текстового ответа: инструмент возвращает Markdown-дайджест
  с подтверждёнными ссылками, отдельными карточками ресторанов Яндекс.Карт и
  warnings.

Для `trip-page/v2` пустой `events` запускает внутри `get_trip_report()`
ограниченный поиск концертов и спектаклей Афиши с проверкой расписания, а пустой
`venues` — `restaurant_search()` вокруг выбранного отеля. HTML и Markdown
получают один и тот же фактический shortlist. Сбой внешнего источника не ломает
отчёт, а добавляет видимое предупреждение.

Явно заданный пользователем режим всегда сильнее значения по умолчанию.
Низкоуровневые `render_trip_page`, `render_travel_page`, `format_trip_reply`,
compose/schema/validate helpers не публикуются в `tools/list`: они остаются
внутренними и локальными API. Если старый MCP-сеанс всё ещё показывает их,
переподключи сервер и используй только `get_trip_report`.

## Размер shortlist

- отдельная подборка отелей — целевое число 5, допустимо 1–5, если подходящих
  доступных вариантов меньше; неполноту обязательно перенеси в warnings;
- полная поездка — ровно 3 отеля: выгодный, сбалансированный и больше комфорта.

Не задерживай ранний chat-ответ ради полной выдачи. Для HTML сначала закончи
обогащение финального shortlist и только потом вызывай renderer.

Если хотя бы один финальный отель не содержит `reviewCount`, `facilities`,
реальные `photos`, `room`, `meal`, `cancellation`, `payment` или полноценный `reviewDigest`,
`get_trip_report` по умолчанию возвращает ошибку `HOTEL_ENRICHMENT_REQUIRED` и не
создаёт итоговый HTML/Markdown. После реального сбоя одного из обязательных
hotel-инструментов добавь конкретный warning с названием или id каждого
затронутого отеля и повтори вызов с
`allow_incomplete_after_source_failure=true`. Только эта явная ветка сохраняет
fail-soft отчёт; использовать её вместо обязательных вызовов нельзя.

Необязательные данные добавляй только при наличии источника и поддержки
в опубликованной схеме request. Сохраняй возвращённые warnings и advice.

## Обогащение финальных отелей

Любой hotel-тул, который возвращает один или несколько отелей, добавляет к
каждому объекту единый блок `details`: `hotelId`, название, звёзды, адрес,
описание, время заезда/выезда, координаты, до 12 удобств, точный `tbankUrl` и до
трёх уникальных HTTPS-фотографий в `imageUrls`. Если карточка или фотографии не
пришли из источника, тул сохраняет основную выдачу и добавляет warning; значения
не подменяются плейсхолдерами. Для одноотельных `hotel_rates` и `hotel_reviews`
тот же блок называется `hotelDetails`.

Для каждого финального отеля используй сохранённую карточку `hotel_search()`,
затем:

1. Одним `hotel_latest_offers()` перепроверь весь shortlist непосредственно
   перед сравнением.
2. Возьми адрес, описание, часы заезда/выезда, удобства и `imageUrls` из
   встроенного `details`. `hotel_details(max_images=3, response_format="json")`
   вызывай только для повторной или расширенной загрузки карточки.
3. Вызови `hotel_rates()` с теми же датами и гостями. Условия номера, питания,
   отмены и оплаты считаются подтверждёнными только при финальной цене.
4. Для каждого отеля загрузи одну сопоставимую страницу
   `hotel_reviews(sort="date", sort_type="desc", page_size=10,
   response_format="json")`.

Hotel-поиск публичный и не требует банковского входа. Если доступна сохранённая
Hotels web SSO-сессия, `hotel_search()` использует её для персональной выдачи;
отсутствие или истечение сессии не должно останавливать анонимный поиск. Bearer
и банковский sessionid в Hotels API не передаются.

## Фото

В HTML сохрани до трёх уникальных реальных HTTPS-фото на отель:

1. сначала официальные `imageUrls` из встроенного `details` hotel-тула;
2. если их меньше трёх, разрешено добавить фотографии из уже загруженных отзывов
   того же отеля с `kind="guest"` и явной подписью «Фото гостя»;
3. если реальных фото всё равно меньше трёх, показывай только найденные — не
   создавай плейсхолдеры, не подставляй похожие отели и не выдумывай URL.

При `get_trip_report(..., output_mode="html")` сервер пытается загрузить
фотографии отелей, событий Афиши и ресторанов с ограниченного списка известных
CDN и встроить их в возвращаемый HTML как `data:` URI. Это позволяет
sandbox-preview показывать фотографии без доступа к внешней сети. Загрузка
ограничена таймаутом, допустимыми MIME-типами, размером одного файла и общим
бюджетом отчёта; крупные изображения перед встраиванием уменьшаются. Исходные
HTTPS URL сохраняются в document JSON; если встроить
часть фото не удалось, report оставляет их внешними ссылками и добавляет warning.
Прямые renderer-тулы и локальный CLI сеть не вызывают.

В chat-режиме покажи первое доступное фото каждого отеля: если хост умеет
показывать локальные файлы (локальный агент), скачай `imageUrl` локальным
файлом по абсолютному пути; если хост удалённый и локальных файлов не видит
(например ChatGPT), используй первое удалённое HTTPS-фото из `details.imageUrls`.
Ошибку загрузки обозначь текстом.

## Обзор отзывов

`reviewDigest` строится отдельно по каждому отелю и содержит:

- фактический `sampleSize`, сортировку и доступный диапазон дат;
- повторяющиеся плюсы и минусы;
- короткое резюме и `suitableFor` («кому подходит»).

Не выдавай выборку за все отзывы. Не называй доли и проценты, если они не
рассчитаны над явно указанной выборкой. Тема считается повторяющейся только если
она встречается минимум в двух загруженных отзывах; иначе напиши «недостаточно
данных». Не смешивай отзывы разных отелей.

## HTML и сравнение

Для отдельной подборки собери `hotel-page/v1`; для полной поездки —
`trip-page/v2`. Оба документа передаются в `get_trip_report()` и рендерятся в
общем UI Travel Nova.

Сравнительная таблица обязательна и содержит строки: полная цена, цена за ночь,
звёзды, рейтинг и число отзывов, расположение, номер, питание, отмена, оплата,
удобства, плюсы по отзывам, минусы по отзывам и «для кого подходит».

`locationSummary` заполняй только фактами из адреса, карточки и доступных
источников. Не угадывай район, расстояние до центра или качество окружения.

`detailsUrl` всегда ведёт на точную страницу отеля T-Bank по настоящему hotel id:
`https://www.tbank.ru/travel/hotels/new/hotels/{hotelId}`. Не создавай её для
фиктивного или невалидного id. `bookingUrl` — отдельный checkout; добавляй его
только для актуального тарифа после явного выбора пользователя, если ссылка
действительно получена через MCP. Ни одна из ссылок не означает бронь или оплату.

В `trip-page/v2` используй подтверждённый `tbankUrl` транспортного сегмента;
`detailsUrl` отеля и авиа-ссылки должны быть точными HTTPS URL T-Bank. Не
подставляй общий раздел T-Bank и не создавай URL по догадке. Рендерер обязан
показывать одинаковое видимое неактивное действие «Ссылка T-Bank недоступна»,
когда точного URL нет.
