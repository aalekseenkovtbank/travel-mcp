# Travel Nova: инструкции для агентов

Этот файл — обязательная корневая входная точка для любого агента, работающего
в репозитории. Он задаёт только общие правила и маршрутизацию. Предметные правила
не копируются сюда: их канонические источники перечислены в
[глоссарии и карте инструкций](docs/AGENT_RULES.md).

## Перед началом работы

1. Прочитай [карту инструкций](docs/AGENT_RULES.md).
2. Определи область задачи по таблице маршрутизации.
3. Полностью прочитай только обязательные для этой области документы и skills.
4. Если документы расходятся, используй порядок приоритетов из карты и явно
   сообщи о существенном конфликте.

## Базовые правила репозитория

- **Не создавай, не изменяй и не запускай автоматические тесты**, тестовые
  фикстуры, snapshots, test runners, test scripts, test-only зависимости и
  тестовые CI-шаги, пока это правило явно не отменено. Проверяй изменения через
  сборку, typecheck, lint и ручную инспекцию.
- Сохраняй незакоммиченные пользовательские изменения и не откатывай их.
- Не выдумывай цены, идентификаторы, расписания, возможности инструментов или
  результаты внешних источников.
- Перед удалением файлов, документов или содержательных правил получи явное
  разрешение пользователя. Сначала покажи точные кандидаты и последствия.
- Не размножай одно правило по нескольким документам. Выбери канонический
  источник, а из остальных мест поставь ссылку на него.

## Общие travel-границы

Этот раздел пока сохранён без сокращения. Он дублирует обязательный
`TRIP_GENERATION.md` и будет заменён ссылкой только после отдельного разрешения.

- Для travel-сценариев предпочитай отдельный `travel-mcp`; полный T-Bank MCP
  допустим для обратной совместимости, но в нём вызывай только read-only
  инструменты поиска, персонализации и внешних источников. Не бронируй и не
  оплачивай билеты, отели или события.
- Не помещай в артефакты банковские операции, доход, зарплату, балансы, документы,
  токены и другие персональные банковские данные. Допустимы только производные
  агрегированные рекомендации.
- Для ресторанов используй публичный read-only `restaurant_search()` из
  Яндекс.Карт; `get_trip_report()` автоматически вызывает его для пустого
  `venues`. Для прогулочных точек и подложки карты используй OpenStreetMap через
  `nearby_search()`. Не смешивай атрибуцию и ссылки источников.
- Итоговая страница создаётся встроенным Travel Nova renderer или CLI
  `render-page` (`render-trip` сохранён для v1); отдельный React/Vite-проект и
  ручная HTML-вёрстка не нужны.
- Checkout-ссылка не является бронью или оплатой. Переход и дальнейшее оформление
  выполняет только пользователь.

## Обязательная маршрутизация

- Для поиска транспорта, подбора отелей, персонализации поездки или генерации
  `HTML + JSON` полностью прочитай
  [TRIP_GENERATION.md](tbank-mcp/docs/TRIP_GENERATION.md) и общие правила режимов
  [TRAVEL_OUTPUT_MODES.md](tbank-mcp/docs/TRAVEL_OUTPUT_MODES.md) до начала поиска.
- Для работы с отдельным `travel-mcp` сначала прочитай travel-router
  [tbank](tbank-mcp/skills/tbank/SKILL.md), затем выбранный им task-specific
  skill: flight, hotel, trip-generation или общий travel-search.
- Для изменения MCP-контракта сверяйся с актуальными схемами, валидаторами и
  сигнатурами инструментов. Исполняемый контракт имеет приоритет над описательной
  документацией; расхождение нужно исправить или явно зафиксировать.

## Поддержка этой системы

При добавлении нового агентского документа или skill обнови
[docs/AGENT_RULES.md](docs/AGENT_RULES.md). Tool-specific адаптеры вроде Cursor
rules должны направлять в `AGENTS.md`, а не содержать отдельную копию политики.
